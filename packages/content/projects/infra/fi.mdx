## Mitä rakensin

Terraform-moduuli, joka pystyttää GitHub Pages -staattisen sivuston koko elinkaaren tyhjästä valmiiseen omaan verkko-osoitteeseen yhdellä `terraform apply` -komennolla. Se luo repon, ottaa Pagesin käyttöön, kirjoittaa CNAME-tiedoston omalle alidomainille ja generoi GitHub Actions -työnkulun, joka hoitaa kaikki tulevat julkaisut. Kolme hackathon-sivustoa (`register.arthurreira.dev`, `schedule.arthurreira.dev` ja `projects.arthurreira.dev`) pystytettiin kaikki tällä tavalla.

## Mitä opin

GitHubin Terraform-providerissa on hienovaraisuuksia, joita pilvipalveluiden providereissa ei ole. GitHubin rajapinta on eventually consistent, joten repon luontia ja Pagesin käyttöönottoa ei aina voi ketjuttaa välittömästi peräkkäin. Se vaati huolellisia `depends_on`- ja `time_sleep`-lohkoja. Syvempi oppi koski sitä, mihin infrastruktuuri koodina oikeasti on: ei vain palvelimien pystyttämiseen, vaan koko asennusprosessin kirjaamiseen niin, että se on toistettava, katselmoitava ja purettava. Terraformin suunnitelma on erotus aiotun ja todellisen infrastruktuurin välillä, ja se malli muuttaa perusteellisesti tapaa ajatella pystytystä.

## Kohokohdat

- Yksi `terraform apply` pystyttää täyden GitHub Pages -sivuston
- Luo repon, ottaa Pagesin käyttöön, asettaa CNAMEn ja generoi julkaisuputken
- Pyörittää kolmea hackathon-alidomainia
- Idempotentti, joten ajon voi turvallisesti toistaa

## Teknologiat

- **Infrastruktuuri koodina:** Terraform ≥ 1.5
- **Provider:** integrations/github ~> 6.0
- **CI/CD:** GitHub Actions
- **Isännöinti:** GitHub Pages
