## What I built

A weather app showing current conditions and short-range forecasts for six cities: Helsinki, Tampere, and Oulu in Finland, and São Paulo, Fortaleza, and Curitiba in Brazil. The city list is a personal choice — Finnish cities because that's where I live, Brazilian because that's where I'm from. The app uses the Open-Meteo API which is completely free and requires no API key, making it trivially deployable without secret management.

The project lives inside the same Turborepo monorepo as the portfolio, consuming the `@arthurreira/ui` design token package. That means the weather app's colours, typography, and spacing stay in sync with the portfolio automatically — when the token package rebuilds, both apps inherit the change. The route architecture splits static city pages (`/helsinki`, `/sao-paulo`) from a dynamic `/api/weather` endpoint that fetches fresh data on each request, keeping build times fast while keeping data current.

Dark mode toggles with the `d` hotkey, consistent with the rest of the ecosystem.

## What I learned

The main insight was about monorepo design token sharing: the pattern works well until you need one app to diverge from the system. AF Weather has slightly different spacing needs than the portfolio, and working out how to override tokens without breaking the shared package taught me where the boundaries of a shared system should live. API design also came up — structuring the weather endpoint so it could serve both the static pages and any future client without rewriting it.
