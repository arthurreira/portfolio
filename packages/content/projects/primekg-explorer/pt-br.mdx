## What I built

A tool for navigating PrimeKG — a Harvard biomedical dataset linking diseases, drugs, genes, proteins, and biological pathways across 4 million+ nodes and relationships. The pipeline loads PrimeKG into a Neo4j graph database, serves it through Next.js API routes, and renders it as an interactive 3D force-directed graph using WebGL via react-force-graph-3d.

You can search by disease, drug, or gene name, filter by entity type, and click nodes to explore their relationships. Node colours are coded by entity type; edge thickness represents relationship weight.

## What I learned

Graph databases think differently from relational ones. A query that would require five JOINs in SQL is a two-hop traversal in Cypher. The mental model shift — "find all neighbours two hops away from this node" vs "JOIN three tables on these columns" — took time but is genuinely more natural for connected data. 3D WebGL rendering also introduced performance constraints I hadn't encountered before: a graph that looks fine at 1,000 nodes becomes unresponsive at 50,000. The solution was LOD (level-of-detail) filtering — showing only high-degree nodes at the global view and expanding detail on zoom.

## Technical Highlights

- Cypher queries via the Neo4j JavaScript driver
- Graph data served through Next.js API routes
- 3D force-directed layout with WebGL rendering
- Node colour-coding by entity type (disease, drug, gene, protein, pathway)
- Search and filter by name or entity type
