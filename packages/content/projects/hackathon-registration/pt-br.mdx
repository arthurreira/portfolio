## O que construí

Três sites estáticos — um formulário de cadastro, uma agenda de eventos e uma galeria de projetos — todos em subdomínios próprios: `register.arthurreira.dev`, `schedule.arthurreira.dev` e `projects.arthurreira.dev`. Os sites em si são intencionalmente simples. O projeto real é a automação Terraform por trás deles.

Um único `terraform apply` cria três repositórios GitHub separados, ativa o Pages em cada um, configura o DNS dos subdomínios e gera o workflow de CD do GitHub Actions para cada repo — sem nenhuma interação manual com a UI do GitHub.

## O que aprendi

O provider Terraform do GitHub é menos previsível que AWS ou Azure: rate limits, delays na criação de repositórios e timing da configuração do Pages exigem cadeias cuidadosas de `depends_on`. Escrever Terraform que provisiona pipelines de CI/CD ensinou como infrastructure-as-code pode gerenciar não só servidores, mas todo o processo de deploy — da criação do repo à URL ao vivo.

## Destaques

- Um único `terraform apply` cria 3 repos + Pages + DNS + workflows de CD
- Sites: register / schedule / projects — cada um em seu próprio subdomínio
- Nenhuma interação manual com a UI do GitHub

## Stack

- **IaC:** Terraform (provider GitHub)
- **CI/CD:** GitHub Actions (gerado automaticamente por repo)
- **Hosting:** GitHub Pages
- **Frontend:** HTML, CSS, JavaScript
