## What I built

Three static sites — a registration form, an event schedule, and a project gallery — all deployed under custom subdomains: `register.arthurreira.dev`, `schedule.arthurreira.dev`, and `projects.arthurreira.dev`. The sites themselves are intentionally simple. The real project is the Terraform automation that provisions them.

One `terraform apply` creates three separate GitHub repositories, enables Pages on each, configures custom subdomain DNS, and generates the GitHub Actions CD workflow for every repo — without touching the GitHub UI once.

## What I learned

The GitHub Terraform provider is less predictable than AWS or Azure: rate limits, repository creation delays, and Pages configuration timing all require careful `depends_on` chains. Writing Terraform that provisions CI/CD pipelines taught me how infrastructure-as-code can manage not just servers but the entire deployment process — from repo creation to live URL.

## Highlights

- One `terraform apply` provisions 3 repos + Pages + DNS + CD workflows
- Sites: register / schedule / projects — all on custom subdomains
- No manual GitHub UI interaction at any step
