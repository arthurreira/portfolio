## What I built

This is not really a hackathon registration tool — it's an infrastructure demonstration. The real project is the Terraform automation that provisions it. Together with `hackathon-schedule` and `hackathon-projects`, these three static sites form a single showcase: one Terraform run creates three separate GitHub repositories, configures GitHub Pages on each, sets up custom subdomain DNS, and generates the GitHub Actions CD workflow — all without touching the GitHub UI.

The registration form itself is intentionally simple: name, email, project idea. The point is the infrastructure around it. Each repo goes from zero to a live custom-domain site through a single `terraform apply`.

## What I learned

The GitHub Terraform provider has a steeper learning curve than the AWS or Azure providers because GitHub's API is less predictable — rate limits, repository creation delays, and Pages configuration timing all require careful `depends_on` chains to work reliably. Writing Terraform that provisions other CI/CD pipelines (GitHub Actions workflows) taught me how infrastructure-as-code can manage not just servers but the entire deployment process.


## What Gets Provisioned

One `terraform apply` creates:
1. GitHub repository (public, named)
2. GitHub Pages enabled via API
3. CNAME file for custom subdomain (e.g. `register.arthurreira.dev`)
4. GitHub Actions workflow for automated deployment on every push
