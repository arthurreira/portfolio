## O que construí

Um dashboard financeiro full-stack criado a partir do curso oficial de Next.js 16, depois ampliado e com deploy em produção. O app gerencia clientes e faturas de uma empresa fictícia chamada Acme, com estatísticas de receita e gráficos interativos no dashboard.

A stack cobre toda a arquitetura do Next.js App Router: Server Components para buscar dados, Client Components para interatividade, Server Actions para enviar formulários e Suspense boundaries para streaming. A autenticação usa NextAuth.js v5, com sessões armazenadas no PostgreSQL da Neon. O deploy foi feito na Vercel em um subdomínio próprio.

## O que aprendi

O maior aprendizado foi entender QUANDO usar Server ou Client Components — e que Server deve ser o padrão. Buscar dados sem `useEffect`, substituir rotas de API por Server Actions nos formulários e fazer streaming com Suspense foram padrões que ficaram claros durante a construção. A autenticação com NextAuth.js v5, ainda em beta, foi trabalhosa: a API mudou durante o desenvolvimento e exigiu leitura cuidadosa dos changelogs. O deploy real também revelou aspectos que o ambiente local esconde, como variáveis de ambiente, seed do banco e a diferença entre os ambientes de preview e produção da Vercel.
