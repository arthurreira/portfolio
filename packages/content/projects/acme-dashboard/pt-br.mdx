## What I built

A full-stack financial dashboard built by following the official Next.js 16 learn course — then extended and actually deployed to production. The app manages customers and invoices for a fictional company called Acme, with a dashboard showing revenue statistics and interactive charts.

The stack covers the full Next.js App Router architecture: Server Components for data fetching, Client Components for interactivity, Server Actions for form submissions, and Suspense boundaries for streaming. Authentication is handled by NextAuth.js v5 with a PostgreSQL session store on Neon. The whole thing is deployed on Vercel with a custom subdomain.

## What I learned

The biggest insight was understanding WHEN to use Server vs Client Components — and that the default should always be Server. Data fetching without useEffect, server actions replacing API routes for forms, and streaming with Suspense were the patterns that clicked through building this. Authentication with NextAuth.js v5 (beta) was rough — the beta API changed during development and required careful reading of changelogs. Real deployment also surfaced things that local dev hides: environment variables, database seeding, and the difference between preview and production Vercel environments.
