## Mitä rakensin

Full-stack-taloushallinnan koontinäyttö, joka syntyi virallista Next.js 16 -kurssia seuraamalla — ja jatkui siitä oikeaksi tuotantojulkaisuksi. Sovellus hallinnoi kuvitteellisen Acme-yhtiön asiakkaita ja laskuja, ja koontinäyttö näyttää liikevaihtotilastot ja interaktiiviset kaaviot.

Pino kattaa koko Next.js App Router -arkkitehtuurin: Server Componentit datan hakuun, Client Componentit interaktiivisuuteen, Server Actionit lomakkeille ja Suspense-rajat striimaukseen. Tunnistautumisen hoitaa NextAuth.js v5, jonka istunnot tallentuvat Neonin PostgreSQL-kantaan. Kokonaisuus on julkaistu Verceliin omalla alidomainilla.

## Mitä opin

Suurin oivallus oli ymmärtää, MILLOIN käyttää Server- ja milloin Client-komponentteja — ja että oletuksen pitäisi aina olla Server. Datan haku ilman useEffectiä, Server Actionit API-reittien tilalla lomakkeissa ja striimaus Suspensella olivat ne mallit, jotka loksahtivat paikalleen tätä rakentaessa. Tunnistautuminen NextAuth.js v5:llä (beta) oli kivikkoista — betan API muuttui kesken kehityksen ja vaati muutoslokien tarkkaa lukemista. Oikea julkaisu nosti esiin myös asioita, jotka paikallinen kehitys piilottaa: ympäristömuuttujat, tietokannan alustuksen ja Vercelin preview- ja tuotantoympäristöjen erot.
