## O que construí

Um app de notas dividido em dois serviços independentes: um frontend em Next.js e um backend REST API separado, executado em Docker. A separação é intencional — os dois repositórios compartilham um pacote de interfaces TypeScript, mantendo o contrato da API tipado nas duas pontas. O frontend consome a API por HTTP, enquanto a API cuida de todo o CRUD e da persistência. Qualquer um dos serviços pode ser substituído ou receber um novo deploy de forma independente.

Funcionalidades: criação, leitura, atualização e exclusão de notas, organização por tags e armazenamento persistente pela API.

## O que aprendi

O principal aprendizado foi o custo das fronteiras entre serviços. Em um monólito, compartilhar tipos é simples. Com dois repositórios separados se comunicando por HTTP, o contrato da API precisa ser pensado com cuidado: qual é o formato das requisições e respostas e como manter os dois lados sincronizados quando ele muda? Gerenciar um pacote compartilhado de tipos me mostrou por que versionamento de API e contratos claros importam mais do que parecem em projetos pequenos.

## Destaques

- Criação, leitura, atualização e exclusão de notas
- Organização por tags
- Frontend Next.js desacoplado de uma REST API em Docker
- Tipos TypeScript compartilhados entre os dois serviços
- Cada serviço pode ser publicado independentemente

## Stack tecnológica

- **Linguagem:** TypeScript (tipos compartilhados)
- **Frontend:** Next.js
- **Backend:** REST API em Docker
- **Transporte:** HTTP
