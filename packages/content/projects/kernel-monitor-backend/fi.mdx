## Mitä rakensin

Kaksi repoa, jotka toimivat yhtenä järjestelmänä. Backend pyörii Linux-koneella: eBPF-ohjelma kiinnittyy `sys_enter_openat`-tracepoint-kohtaan ja kaappaa jokaisen tiedostonavaustapahuman — PID, prosessin nimi, tiedostonimi — ja kirjoittaa sen SQLiteen. FastAPI-palvelin tarjoaa `/ask`-endpointin, joka ottaa vastaan luonnollisen kielen kysymyksen, hakee tapahtumatietokannasta ja lähettää tulokset paikalliselle phi3:mini-mallille Ollaman kautta vastausta varten.

Frontend on Next.js-chat-käyttöliittymä, joka pyörii Macilla, lähettää kysymykset FastAPI-backendille paikallisverkon kautta ja näyttää vastaukset.

```
React chat -käyttöliittymä (Mac)
    → HTTP POST FastAPI:lle (Linux-kone)
        → SQLite-kysely (oikeat eBPF-ytimentapahtumat)
            → phi3:mini Ollaman kautta (paikallinen tekoäly)
                → vastaus
```

Voit kysyä: *"Mikä prosessi on aktiivisin?"*, *"Mitä Docker tekee?"*, *"Onko mitään epäilyttävää?"* — ja saat vastaukset oikeaan ytimen dataan perustuen.

Ei pilveä. Ei API-kuluja. Ytimen data ei poistu paikallisverkosta.

## Mitä opin

eBPF on suorin tapa tarkkailla, mitä Linux-järjestelmä oikeasti tekee. Tracepoint-kohtaan kiinnittyminen `/proc`-pollauksen sijaan tarkoittaa, että näet kaiken — ei otantaa, ei aukkoja. Insinöörihaasteena oli tehdä raaasta tapahtumavirrasta hyödyllistä: "kaappaa jokainen openat-syscall" -tiedon muuntaminen vastauksiksi kysymyksiin kuten "onko mitään epäilyttävää?" vaati SQL-to-LLM-putken, joka tiivistää tuhansia tapahtumia hyödylliseksi lauseeksi.

Paikallinen inferenssi Ollaman + phi3:minin kanssa oli tietoinen valinta. Se poistaa API-kutsujen viiveen, eliminoi kulut ja tarkoittaa, että ytimen data ei koskaan poistu koneelta — mikä on tärkeää, kun data sisältää jokaisen järjestelmän koskettaman tiedoston.

## Kohokohdat

- eBPF-tracepoint-koukku `sys_enter_openat`-kohdassa — kaappaa jokaisen tiedostonavauspyynnön
- SQLite-tapahtumavarasto — kyseltävissä SQL:llä
- FastAPI `/ask`-endpoint luonnollisen kielen kyselyille
- Paikallinen LLM-inferenssi Ollaman kautta (phi3:mini) — ei pilveä, ei API-kuluja
- Next.js-chat-käyttöliittymä kommunikoi backendin kanssa paikallisverkon kautta
- Testattu ytimellä 6.17, Ubuntu 24

## Teknologiat

- **eBPF:** BCC (Python-sidokset)
- **Backend:** Python, FastAPI, uvicorn, SQLite
- **Tekoäly:** Ollama, phi3:mini (paikallinen inferenssi)
- **Frontend:** Next.js 15, TypeScript, Tailwind CSS
