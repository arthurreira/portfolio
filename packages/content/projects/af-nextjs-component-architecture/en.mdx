## What I built

A monorepo component library built to practice the atomic design methodology from first principles. Two workspaces: a `packages/ui` shared library where every component lives, and an `apps/playground` Next.js app used to render and test them. The hierarchy runs atoms → molecules → organisms, each layer only composing from the layer below. All component props are strictly typed with TypeScript interfaces — no implicit `any`.

## What I learned

The main insight was that atomic design is a communication tool as much as a technical pattern. The discipline of asking "is this an atom or a molecule?" forced clearer thinking about component responsibility. The pnpm workspace setup also taught me how shared packages are resolved differently from npm packages — and why monorepos require explicit dependency declarations between workspaces rather than relying on hoisting.

## Highlights

- Atomic design hierarchy: atoms → molecules → organisms
- Shared component library in a pnpm workspace package
- Strict TypeScript prop typing across every component
- Playground app for isolated component testing
