## O que construí

Uma biblioteca de componentes em monorepo criada para praticar a metodologia de atomic design desde os princípios básicos. São dois workspaces: a biblioteca compartilhada `packages/ui`, onde ficam todos os componentes, e o app Next.js `apps/playground`, usado para renderizá-los e testá-los. A hierarquia segue átomos → moléculas → organismos, e cada camada compõe apenas elementos da camada anterior. Todas as props são estritamente tipadas com interfaces TypeScript — sem `any` implícito.

## O que aprendi

O principal aprendizado foi perceber que atomic design é tanto uma ferramenta de comunicação quanto um padrão técnico. A disciplina de perguntar “isto é um átomo ou uma molécula?” me obrigou a pensar com mais clareza sobre a responsabilidade de cada componente. A configuração dos pnpm workspaces também me ensinou que pacotes compartilhados são resolvidos de forma diferente de pacotes npm — e por que monorepos exigem dependências explícitas entre workspaces, em vez de depender de hoisting.

## Destaques

- Hierarquia de atomic design: átomos → moléculas → organismos
- Biblioteca de componentes compartilhada em um pacote do pnpm workspace
- Props estritamente tipadas com TypeScript em todos os componentes
- App playground para testar componentes isoladamente

## Stack tecnológica

- **Framework:** Next.js
- **Linguagem:** TypeScript
- **Monorepo:** pnpm workspaces
- **Estilos:** Tailwind CSS
