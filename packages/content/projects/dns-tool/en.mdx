## What I built

A DNS lookup tool that lets you query any domain for six record types: A, AAAA, MX, TXT, CNAME, and NS. The interface is built with Next.js and shadcn/ui — enter a domain, pick a record type, get structured results immediately. A query history panel on the right tracks previous lookups so you can compare results across domains or record types without re-typing.

The DNS resolution itself runs on an AWS Lambda function rather than the Next.js server. The frontend calls an API route that proxies to the Lambda, which performs the actual DNS queries. This split keeps the Next.js deployment lightweight and makes the resolution logic independently scalable and testable. The whole stack deploys to `dns.arthurreira.dev`.

## What I learned

The interesting engineering problem here was latency. DNS resolution involves network round-trips that are inherently unpredictable, and the Lambda cold-start penalty made the first query after idle noticeably slow. Reducing that required understanding Lambda provisioned concurrency, the trade-off between keeping functions warm and cost, and how to structure the API route to return a loading state immediately while the resolution completes. It also pushed me to think seriously about error states — DNS queries can fail for many reasons (NXDOMAIN, SERVFAIL, timeout), and each failure mode needs a different user message.


## Features

- Query A, AAAA, MX, TXT, CNAME, NS records for any domain
- Query history panel — compare results across domains without re-typing
- Structured JSON-style result display
- Error states per failure type (NXDOMAIN, SERVFAIL, timeout)
- Deployed at [dns.arthurreira.dev](https://dns.arthurreira.dev)

## Tech Stack

- **Frontend:** Next.js, TypeScript, shadcn/ui, Tailwind CSS
- **Backend:** AWS Lambda (serverless DNS resolution)
- **Deployment:** Vercel (frontend) + AWS (Lambda)
